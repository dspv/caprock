# Caprock — Engineering rules (binding for this repo)

These rules are binding. `CLAUDE.md` links here; an agent reads this file before touching code. Each rule names the failure it prevents. Tooling and versions are in [10-infrastructure.md](10-infrastructure.md).

## From the spec (Part II §5)

- **English everywhere:** code, comments, commits (Conventional Commits), PRs, docs.
- **Agent docs live in `.ai/`** — the `.ai/` corpus is the source of truth; Claude Code reads it before any task. (The spec's SPEC.md/PHASE0.md have been absorbed into `.ai/`; the spec is deleted after the loss audit — [docs/migration-audit.md](../docs/migration-audit.md).)
- **One focused change per PR** with its rationale in the description; run `make check` first. During the T0–T25 build each PR referenced its task ID and pasted its acceptance criteria as a checklist, under the bootstrap amendment [ADR-014](08-decisions.md#adr-014--commit-to-master-directly-until-phase-0-t6-then-prs) (commit-to-master until T6, PRs from T7). **That build is complete (all of T0–T25 shipped); there are no more T-tasks.** Ongoing changes are ordinary PRs to `master` — one focused change each, still green on the 3-OS matrix.
- **No task is done with a red Windows job. No exceptions** — this is the moat ([02-architecture.md § Cross-platform](02-architecture.md#cross-platform-do-it-right-on-day-one)).
- **Unknown hook events and unknown transcript fields are logged and ignored, never fatal** ([12-risks.md](12-risks.md) RISK-01, RISK-02).
- **The shim must never break a user's Claude session:** any error path = silent `exit 0`. Enforced by `internal/shim/shim_test.go`, which covers the failure paths rather than the happy one (the smoke suite already runs that end to end): no daemon, a stale `runtime.json` pointing at a dead port, a corrupt `runtime.json`, malformed or oversized stdin, a daemon that never answers, a non-200, a non-JSON reply, and a panic raised inside `Run`. Two invariants the tests assert directly — nothing but valid JSON ever reaches stdout, since Claude Code parses whatever the shim prints, and an ordinary hook returns well inside its budget even when the daemon hangs. Each test was verified to fail against a deliberately broken shim; a test that cannot fail is not enforcement.

## Repo-level rules (added while preparing the repo, 2026-08-18)

- **Every task ends green:** `go vet ./...`, `go test ./...`, `golangci-lint`, `ui` typecheck + tests, and the docs gates — `make check` runs all of it — locally before push, and in CI on all three OS. A push that reddens CI is fixed or reverted in the next commit, never left for later; a red main branch hides the next regression.
- **Pure Go only** — no CGO anywhere. `modernc.org/sqlite`, no `mattn/go-sqlite3`. The reason is cross-compiling one static binary per OS from one runner; a single CGO dependency reintroduces the ABI-class install failures Munder Difflin suffers.
- **No outbound network calls the user did not ask for.** The only sockets are `127.0.0.1` listeners and loopback POSTs from the shim; nothing about the user is ever sent anywhere. Four calls leave the machine, each off until someone turns it on, each to a destination that person chose, and three more are one message the user sends on a click:
  - the **release check** (`internal/update`) asks `api.github.com` for a version tag — off by default, offered once, revocable, due every 15 minutes and on focus but never more than once per ten minutes unless the user asks, and conditional (an unchanged release is a 304), no body, credentials or usage data; with **Update automatically** chosen in the desktop app, a newer version found there is then fetched from GitHub's release downloads (`latest.json` and the signed bundle, the same requests a click on Update makes) ([ADR-042](08-decisions.md), amended 2026-10-15 and 2026-10-16);
  - **Gemini** (`internal/gemini`) POSTs the user's own prompt to `generativelanguage.googleapis.com` on the user's own key, and only when they ask a question ([ADR-023](08-decisions.md), [ADR-025](08-decisions.md));
  - **Telegram** (`internal/weekly`, `internal/telegram`) — the weekly report's figures, the phone alerts and the two-way chat — talks to `api.telegram.org` only, through a bot the user created, to the one chat they paired; it reads updates by long polling only while that bot has something to answer, and never listens for a connection ([ADR-024](08-decisions.md), [ADR-036](08-decisions.md), [ADR-047](08-decisions.md));
  - **GitHub** (`internal/github`) calls `api.github.com` (and `github.com` for the device flow) with the user's own token once they connect it in Settings; disconnecting stops it, polling is conditional and at most once a minute — except the CI views (a PR's CI, the repository's release build and its default branch, on the Pipeline page and in the inspector's CI and release blocks), which ask every 10–20 s while a check or job runs, only while the page is in front or the block unfolded and the window visible — and the token is sent nowhere else ([ADR-039](08-decisions.md)). A failed job's log, asked for by a click, is downloaded from the signed address GitHub redirects to on its log storage (`*.actions.githubusercontent.com`, `*.blob.core.windows.net`), without the token.

  - the **offer survey** (`internal/api/offer.go`, `ui/src/components/OfferStrip.tsx`) POSTs one answer to `caprock.dev/api/offer` — which offer, its two one-click choices and an email only if typed — only when the user presses **Send** on a card that says so; dismissing it sends nothing, and an answered card never returns ([ADR-062](08-decisions.md)).
  - **Report a bug** (`internal/api/support.go`, `ui/src/components/BugReportSheet.tsx`) POSTs one report to `caprock.dev/api/support` — the text the user typed or dictated, up to three screenshots they attached, an email only if typed, and the Caprock version and OS the daemon adds — only when the user presses **Send to support** on a sheet that names every one of those fields above the button; never to GitHub, because a report may hold personal data; no retry, no queue, nothing logged ([ADR-073](08-decisions.md)).
  - **A share card's link** (`internal/api/sharecard.go`, `ui/src/components/ShareActions.tsx`) POSTs the PNG the share sheet drew (the share card, the Pipeline card, or a dashboard panel's picture from its share menu, `ui/src/components/PanelShareSheet.tsx`) — the picture alone, at most 2 MB — to `caprock.dev/api/card` only when the user presses **X**, **Threads** or **LinkedIn**, whose tooltips say so, so the post links to a page whose preview is that card; Share…, Copy image, Save image and My Telegram never upload. The delete token the site answers with stays in the daemon (`shared_cards`), and **Remove the shared picture** (after posting, and in Settings → Privacy) sends `DELETE caprock.dev/api/card/<id>` with it. A failure falls back to the clipboard; no retry, no queue ([ADR-086](08-decisions.md)).

  Nothing else is sent to Caprock: no identifier, usage figure or anything automatic. Any new outbound call needs the same treatment — an integration the user turns on, off by default, revocable, to a destination the user picked, and saying on the screen that turns it on what it sends ([ADR-047](08-decisions.md)) — or it does not land. Local-first is a promise, not a default.
- **Data dir writes go through `internal/store` and `internal/hive` only.** No `os.WriteFile` to the data dir from handlers. Atomic writes (`tmp` + rename) for every file that another process may read (`runtime.json`, task files, mailboxes).
- **Every child process starts through `internal/hidewin` on Windows.** `hidewin.Command`/`CommandContext` (or `hidewin.Hide` on a command built by hand) give the child a console with no window. The daemon runs without a visible console, and a console program started from it otherwise opens a window of its own: on Windows 10 it flashed every few seconds (git polling) and stole the keyboard focus, which made a release unusable there (user report, 2026-10-15). The daemon itself starts with a hidden console (`CREATE_NO_WINDOW`), not `DETACHED_PROCESS`, so grandchildren such as git's ssh and credential helpers share it. `TestEveryCommandIsHidden` fails on a bare `exec.Command` outside a short, reasoned allowlist.
- **All paths via `filepath`; no `sh -c` anywhere in production code.** Verification commands (Phase 2) run through a small cross-platform runner that spawns the platform shell explicitly (`cmd /C` on Windows, `/bin/sh -c` on POSIX) and is covered by the three-OS smoke test.
- **Contracts change with their docs in the same commit.** New endpoint → `03-contracts.md`; new table/column → DDL section + a migration; new hook event consumed → the shim table + installer. A contract that exists only in code is not a contract.
- **Cost math is data-driven.** No price literal in Go outside `pricing/pricing.json` (models) and `pricing/actions.json` (GitHub Actions runners, with its own version). `meta.pricing_version` records the table version in force; cost rows are computed at write time with that version and never recomputed retroactively; a pricing update ships as a new version + changelog line, never as an in-place edit of an existing entry.
- **No invented numbers in UI copy or docs.** A forecast is labeled "estimate"; a stat that isn't measured is not shown.
- **Errors are values, and logs are structured.** `log/slog` with `session_id`, `component`, and `event` fields; no `fmt.Println` in library code; `panic` only for programmer errors at init.
- **Tests before hardening, fixtures before mocks.** Prefer golden-file tests on real transcript fixtures (`testdata/`) and `httptest` over mocks; the fake `claude` (T10) is a real subprocess emitting real hook calls.
- **UI: strict TypeScript, no `any`;** components derive every color/size from `ui/src/design/tokens.css` ([04-ui.md § Visual direction](04-ui.md#visual-direction-v0-tokens)); numbers render in monospace with tabular numerals.
- **Commits: Conventional Commits with scope** — `feat(hookd): …`, `fix(ingest): …`, `docs(ai): …`, `ci: …`, `chore(release): …`. Commit bodies explain *why* when the diff does not.
- **The changelog is one file per change.** A pull request adds `changes/unreleased/<pr-or-branch-slug>.md` (front matter `kind: Added|Changed|Deprecated|Removed|Fixed|Security`, then its `- **scope:** …` bullets) and never edits `CHANGELOG.md`; the release runs `scripts/changelog.py assemble X.Y.Z YYYY-MM-DD`. Every PR editing `[Unreleased]` made git conflict and, on 2026-10-15, merge three entries silently into sections already released. Format: [changes/README.md](../changes/README.md); `make docs-check` validates it.
- **A pull request never carries the built dashboard.** `internal/api/dist` is committed so `go install` embeds a real UI, but only `.github/workflows/dist.yml` writes it: after each merge that touches `ui/`, it runs `make ui` on master and commits `chore(dist): rebuild the dashboard for <sha>` when the output differs. CI's `no dist in the PR` job and `make check` (`dist-untouched`) fail a branch that changes it; `make dist-reset` puts it back. The bundle's file names are content hashes, so every two PRs that both rebuilt it conflicted there: on 2026-10-15 four PRs (#663, #667, #669, #670) were hand-merged, some twice, for that alone. A tag must hold its own `ui/` built (`make release-ready` and release `verify` run `dist-check`), so a release is tagged after master's rebuild commit lands ([ADR-068](08-decisions.md#adr-068--the-dashboard-bundle-is-rebuilt-on-master-never-carried-by-a-pull-request)).
- **Docs discipline** — tight-aligned tables via `make docs-fmt`, one fact one home, ADRs for closed debates, absolute dates: see [00-index.md § Documentation rules](00-index.md#documentation-rules).

## Council quorum for decisions (agents deciding, not decorating)

When a design or correctness call is non-obvious and the agent is not sure, it convenes a **council** of independent sub-agents and decides by an escalating quorum — so the council actually forces a correct decision rather than rubber-stamping one:

- **Round 1 — ask 3.** Pose the same crisp choice to 3 independent agents. If **all 3 agree**, that is the decision — proceed.
- **Split → escalate.** If they do **not** all agree (e.g. 2-of-3), the split is a signal the question is genuinely hard: convene **5** agents on the same question. A clear majority of 5 decides.
- **Still split → escalate again** (7, then 9…), each round adding two agents, until a clear majority holds. If a small council keeps splitting, the question is under-specified — reformulate it or **escalate to the human**, don't force a coin-flip.

Rules that keep it honest:

- **Independent, then counted.** Agents must answer without seeing each other's answers; only then are votes tallied. A council where later agents read earlier ones is theatre.
- **Adversarial where it matters.** For a correctness or safety claim, at least one council member is tasked to *refute* it, not confirm it. Unanimous "looks fine" from confirmation-only agents is weak evidence.
- **The parent still owns the outcome.** The quorum informs the decision; it does not launder responsibility. If the majority is wrong on the merits and the parent can see why, the parent overrides and records why.
- **Scale to the stakes.** Trivial or reversible choices don't need a council at all — pick the obvious option and move. The council is for calls that are hard to reverse or that the docs leave genuinely open.

## Definition of "green" per task

1. Unit + integration tests pass on ubuntu / macos / windows.
2. `golangci-lint run` clean; `go vet` clean.
3. UI: `tsc --noEmit`, `vitest`, `vite build` clean.
4. `make docs-check docs-links` (tables + links + anchors) clean.
5. `14-build-status.md` and README progress updated in the same commit when a track moves.
